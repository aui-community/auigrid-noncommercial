샘플 목록문서

이 패키지는 별도의 데이터 서버 없이 포함된 예제 데이터로 조회, 검색 및 페이지 이동을 시연합니다. 웹 서버의 HTTP(S) 주소로 실행하고, 실제 프로젝트에서는 데이터 요청 부분을 서버 API에 연결하십시오.

서버의 전체 데이터에서 필요한 페이지 20건만 조회할 수 있습니다. 페이지를 이동할 때마다 해당 데이터만 받아 그리드에 표시합니다.

칼럼 헤더를 클릭하면 전체 검색 결과를 기준으로 정렬합니다. Shift를 누른 채 다른 헤더를 클릭하면 다중 정렬할 수 있습니다. 검색 조건이나 정렬을 바꾸면 첫 페이지로 이동합니다.

한 페이지에 20건씩 조회합니다.

서버 페이징의 정렬, 필터 및 연동 방법

이 예제의 PHP 서버는 고정된 예제 자료를 10,003건으로 확장하여 사용합니다. 브라우저에 전체 자료를 보내지 않으며, 응답에는 요청한 페이지의 최대 20건과 전체 건수, 검색 결과 건수만 담습니다.

서버에서 필터 → 정렬 → 페이지 추출 순서로 처리합니다. 같은 정렬값에는 고유 주문 번호를 추가 기준으로 사용합니다. 고객명과 제품명은 부분 검색, 국가는 일치 검색, 금액은 최솟값 조건이며 조건 사이는 AND로 결합합니다.

기본 그리드 필터 메뉴는 현재 로드된 데이터만 알 수 있으므로 이 예제는 별도의 서버 검색 영역을 사용합니다. 헤더 필터 메뉴까지 연동하려면 서버에서 전체 값 목록과 검색 조건을 제공하는 별도 UI가 필요합니다. 

// 헤더 정렬은 표시만 하고, 이벤트의 모든 정렬 조건을 서버에 전달합니다.
const gridProps = { usePaging: false, useCustomSorting: true, enableFilter: false };
// GET ./data/getServerPaging.php
// page=1&pageSize=20&sort=[{"dataField":"price","sortType":-1}]&country=Korea
// 응답: { items: [...최대 20행], totalRows: 10003, total: 검색결과건수,
//         page: 1, pageSize: 20, totalPages: 검색결과페이지수 }
AUIGrid.setGridData(myGridID, response.items);

실서비스에서는 PHP의 예제 배열 처리를 DB 조회로 바꾸십시오. 동일한 WHERE 조건으로 COUNT와 데이터 조회를 수행하고, 허용한 필드로만 ORDER BY를 구성한 뒤 LIMIT/OFFSET을 적용합니다. 데이터 변경이 잦다면 일관된 조회 시점 또는 커서 기반 페이지 이동도 검토하십시오.

이 예제는 조회 전용입니다. 페이지를 바꾸면 선택 상태가 초기화되며, 그리드의 복사와 내보내기는 현재 로드된 페이지에 한정됩니다. 전체 결과 내보내기와 편집 내용 저장은 같은 검색 조건을 사용하는 별도 서버 기능으로 구성하십시오.
